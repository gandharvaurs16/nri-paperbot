# NRI Paperbot — delivery-only Indian equity simulation

**Paper trading only.** There is no broker client, order endpoint, or live-order path in this repository. Starting cash is ₹1,00,000. The first observation date is 28 September 2026; a milestone report is produced after 27 October 2026, and the schedule keeps running. The modeled account is Zerodha **NRO non-PIS**. This is software for learning, not financial advice.

## Read this first

This project is designed to fail closed. It will **not** buy merely because Claude names a stock. A current Nifty 200 snapshot, validated OHLCV, trend and liquidity setup, a recently verified NRI/broker approved-symbol list, and all code-enforced limits must pass. The starter approved list is empty. The first scheduled run therefore reports prices and candidates if data is available, but places no paper trade until that list is supplied and dated. Its freshness expires after seven days. There is no reliable public Zerodha NRO non-PIS eligibility API built into this project; maintaining the list is a human setup/maintenance task. Thus truly indefinite, unattended *trading* cannot be promised. Unattended reporting and fail-safe pausing can continue.

A free Yahoo Finance feed can rate-limit, delay or correct data. If a required price, calendar, API response, or eligibility check fails, the run logs an incident, sends an optional alert, and does not advance the trading ledger. The later retry cron can try again. GitHub cron can be delayed or skipped. The scheduler is a best-effort service, not a guaranteed execution clock. Public GitHub Pages exposes the ledger, trading history, and any reasoning; use a separate paper account and never put personal or secret information in the ledger.

## What happens each day

1. The workflow runs at 10:45 UTC (16:15 India time), Monday–Friday, with a 12:30 UTC retry. It fetches the official NSE trading and clearing calendars. Weekends and CM holidays become `market closed` session records. The starting holiday files are seeded from NSE circulars; current/future years refresh from the NSE API. If calendar verification is stale, trading fails closed.
2. It takes a dated Nifty 200 constituent CSV, Yahoo's *unadjusted* daily OHLCV and Nifty 50 `^NSEI`. It rejects missing, inconsistent, stale, sub-₹50, nontrading-volume, >35% unexplained moves, and unverified splits. A held stock or pending order with missing bars stops the entire day. A missing prospective candidate is skipped and logged. Historical news is omitted rather than backfilled with future headlines.
3. Before changing the ledger, it asks Claude Sonnet (`claude-sonnet-5-5`) for a strict JSON response. If the API fails or its response is invalid, no fills occur. This favors consistency over pretending a missed stop was executed. A later retry processes the date in order.
4. Previously queued orders use today's opening price with 0.1% adverse slippage. Buys are resized and checked again using that open. Sell cash is unavailable for a new buy until the next NSE trading/clearing session. Shares cannot be sold on their purchase date.
5. The day's high/low tests stops and targets. If both touch, the stop is assumed first; a stop gap sells at the open if worse. A buy-day stop or target is queued for the next session because this is delivery-only. Daily OHLC does not reveal the actual intraday trigger time. Paper stops cannot guarantee a 10% portfolio loss cap in a gap.
6. Claude receives as-of portfolio state, Nifty indicators, qualifying candidates, current dated headlines, and rules. It can propose up to three actions. Code enforces the approved universe, 0.5% equity risk/trade, 6 positions, 20% per stock, 35% per sector, 20% cash, 3% aggregate initial stop risk, a 2R target, and a Nifty 200-day trend filter. A 5% drawdown halves new risk. At 10% observed close/intraday-mark drawdown, all positions are queued to sell at the next open and new buys stop indefinitely until the operator intentionally starts a new simulation.
7. Trades, fees, separate approximate taxes/TDS, daily summaries, decisions, rejected setups, and price sources are written to JSON and committed. A Friday review may change at most two bounded *strategy* filters, only when at least eight round trips and two losses occur in that week. Hard risk limits are immutable to Claude. Loss post-mortems classify ordinary stop losses versus cases needing review.

The starting strategy is a liquid, trend-following 20-session closing breakout with 50/200-day trend, volume at least 1.2× its 20-day average, median 20-day turnover at least ₹10 crore, positive 60-day momentum, and Nifty above its 200-day average. It is deliberately selective; a no-trade day is normal. The AI chooses among qualifying names and may hold or sell, but cannot bypass the deterministic gate.

## Setup without programming experience

You need a [GitHub](https://github.com/signup) account and an [Anthropic Console](https://console.anthropic.com/) account with API billing enabled. Neither service can be configured from this downloaded ZIP by us. Steps use GitHub's web interface.

1. **Create the repo.** On GitHub, choose **New repository**, name it `nri-paperbot`, choose **Public** for free GitHub Pages/Actions, and create it without a starter README. Public means all ledger data is public. Extract this ZIP on your computer. In the repo choose **Add file → Upload files**, drag the *contents of the `nri-autobot` folder* into the upload area, and commit to `main`. GitHub's web upload may not preserve dotfolders in some browsers; check that `.github/workflows/paperbot.yml`, `backtest.yml`, and `test.yml` exist in the repository. If not, use GitHub Desktop to add the extracted folder and publish it, or upload those files through its editor.
2. **Add the API key.** In Anthropic Console create an API key and set a spend limit. In GitHub go to **Settings → Secrets and variables → Actions → New repository secret**. Name it `ANTHROPIC_API_KEY`, paste the key, and save. Never put the key in a file or issue. The model name is configured in the workflow and can be changed if Anthropic retires its alias; check the current model documentation before doing so.
3. **Verify stock eligibility before enabling entries.** In `config/eligibility.json`, enter an `approved` array of NSE symbols verified for your actual Zerodha NRO non-PIS route and applicable foreign ownership/sector restrictions, an ISO `checked_on` date, and a human-readable `source` such as a dated broker confirmation. Keep `blocked` for excluded scrips. Example: `{"checked_on":"2026-09-28","source":"Zerodha NRO non-PIS eligibility checked on 2026-09-28","approved":["INFY"],"blocked":[]}`. **The example is syntax, not a claim that INFY is currently eligible.** Update this at least weekly. If you cannot verify eligibility, leave it empty; the bot will remain in cash. PIS caution/ban restrictions are not themselves the NRO non-PIS rule according to Zerodha, but other broker/ownership restrictions can still matter.
4. **Enable Actions.** Open the repo's **Actions** tab and enable workflows if prompted. Open **Validate paper bot**, choose **Run workflow** (if GitHub displays it), or inspect the test run created by the first push. It should pass the deterministic tests and JavaScript syntax check.
5. **Enable Pages.** In **Settings → Pages**, set **Build and deployment → Source: GitHub Actions**. In **Actions**, open **NRI paper bot → Run workflow → Run workflow**. At or after 16:15 IST on a trading day it should process the day. Before that time it will say data is not due. After the deploy job finishes, the Pages URL appears under Settings → Pages, usually `https://YOURNAME.github.io/nri-paperbot/`. It can take a few minutes. This is a *public static dashboard* reading the committed `docs/state.json`.
6. **Optional one-way Telegram alert.** Create a bot with Telegram's BotFather, obtain your chat ID, and store `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` as separate GitHub Actions secrets. Do not send commands to the bot; it only sends a summary. On data/API failure, inspect **Actions → NRI paper bot** and `data/state.json`'s `incidents` and `status` fields even if an alert is unavailable.
7. **Check each first week run.** In Actions inspect the run and the committed `data/state.json`; the Dashboard's **Run ledger** shows closure, rejection, and trades. If there is no new commit, look at the failed step and the alert. Github Actions does not guarantee a cron run. You can manually select **Run workflow** as a fallback; the ledger skips already processed dates and catches up in order, subject to having archived constituent snapshots and data.

The calendar begins with seeded historical NSE holiday dates and refreshes official current-year CM/clearing data. For 2027 or later, the API must provide that year's calendar or runs will stop. For reliable unattended execution, add external monitoring for missed GitHub runs and a licensed market-data plus current eligibility source. There is no live brokerage connection to configure.

### Local test, if you can run a terminal

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m bot.main --date 2026-09-28
```

The last command needs the Anthropic key in `ANTHROPIC_API_KEY` and live data. It should be run after the market data is published. On Windows use `.venv\\Scripts\\activate` in Command Prompt instead. The GitHub workflow provides the simpler no-terminal test route.

## Two-year historical replay

The **same `process_day` execution/risk engine** handles live and backtest dates. The repository includes a manual **Two-year backtest** workflow with defaults 28 September 2024–27 September 2026. It deliberately will **not** produce a performance figure from today's Nifty 200 members applied backward. Before running it, populate `config/universe_history/YYYY-MM-DD.csv` with dated Nifty 200 constituents from the time, at least one snapshot every 31 days, beginning on/before the first replay date. Each CSV must have `Symbol` and `Industry` (or `Sector`) and at least 150 constituents. The starter archive is empty. Also supply `config/eligibility_history/YYYY-MM-DD.json` snapshots at least weekly, dated no later than their sessions. A single current approved list is not valid for two years. **Do not interpret a cash-only output as a strategy backtest.** A full two-year, trade-producing result requires adding point-in-time eligibility snapshots and robust licensed OHLCV/corporate-action data to the adapter. Yahoo has already returned rate-limit errors in our attempted historical download. No two-year performance claim is included in this deliverable. See `BACKTEST_STATUS.md` for the attempted run and exact blocking reason.

For a fully sourced replay, obtain historical Nifty 200 membership, weekly approved lists, and robust corporate-action-aware OHLCV as they were known each day, and then run **Actions → Two-year backtest → Run workflow**. This uses many Claude calls; apply an API budget. The workflow uploads `backtest_output.json` as an artifact only on success and leaves the live ledger untouched. Its default period includes about 500 trading sessions; it is not a quick unit test. The included deterministic tests validate settlement, costs, risk sizing, drawdown lock and API failure behavior, but are **not** a market backtest.

## Files and records

- `bot/main.py`: catch-up runner; `market.py`: NSE calendar, constituent snapshot and OHLCV adapter; `brain.py`: strict Claude response; `engine.py`: deterministic fills, costs, settlement and risk; `report.py`: 30-day report; `notify.py`: one-way alert.
- `config/settings.json`: immutable operational limits and initial strategy; `config/holidays_*.json`: official dated holiday seeds/cache; `config/eligibility.json`: approved/blocked symbols; `config/universe_history/`: archived constituent CSVs.
- `data/state.json`: canonical paper ledger. `docs/state.json`: identical public copy for Pages. Do not manually edit one without the other. `docs/index.html`, `styles.css`, `app.js`: responsive static dashboard with dark/light mode and JSON export.
- `.github/workflows/`: scheduled paper run, tests, manual backtest. Repo commits provide an audit trail. Back up the repository and dashboard's **Export backup** JSON; GitHub history is not a substitute for an external backup.

## Modeling boundaries

Transaction costs estimate Zerodha NRO non-PIS delivery brokerage `min(0.5% of turnover, ₹50)` per executed order, STT 0.1% each side, NSE transaction 0.00307% each side, SEBI ₹10/crore each side, GST 18% on brokerage/exchange/SEBI, stamp duty 0.015% buy, DP ₹15.34 per sold scrip per day, and IPFT. Rounding, corporate-action credits, interest, banking, regulatory changes and actual contract-note charges may differ. Tax and TDS are reported separately rather than removed from trading cash. The estimates use 20% STCG/12.5% LTCG base and indicative NRI TDS rates; exemptions, thresholds, surcharge, cess, treaties, loss set-off and tax residency need independent review. Update rates when they change.

Daily bars cannot establish within-day sequence; the stop-first assumption is conservative but a simulated stop at the printed level may still be optimistic for an illiquid or gapping stock. A 10% threshold is a **liquidation rule**, not a guarantee of maximum realized drawdown. No strategy should be trusted after a 30-day sample. Before considering real money, seek at least 12–24 months of forward paper evidence across market regimes, roughly 100 independent round trips, stable results after all costs and taxes, and a verified data/execution audit. Even that cannot prove future returns. Do not activate real trading from this code.

## Estimated running cost (September 2026 prices, illustrative)

Claude Sonnet 5.5 API pricing is $2 per million input tokens and $10 per million output tokens. At an **assumed** 8,000 input + 1,000 output tokens each trading day, one call costs about $0.026, or $0.57 for 22 sessions. Weekly reviews, longer payloads, retries and output variation might make this roughly **$1–$5/month**; set a spend cap and check actual API usage. A 500-session historical replay under the same assumption is about **$13** before weekly review calls and retries. Public GitHub Actions and Pages can fit in free usage limits; a licensed market-data feed, paid GitHub plan, Telegram delivery or monitoring service may cost extra. Yahoo is free but has no service guarantee. Dollar-to-rupee conversion is intentionally omitted because exchange rates change.
